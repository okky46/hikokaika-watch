# 意図のすり合わせと手動登録導線の確認

2026-09-29。仕様のすり合わせ中。コード・SQL・本番データは変更していない。

## 管理者から確認できた意図

- 管理者が把握した市場の噂だけでも銘柄を登録し、一覧・詳細へ載せたい。記事は必須にしない。
- 一覧で最初に伝えるのは「どの媒体・どんな噂で注目され、今どうなっているか」。確認作業の説明を主役にしない。
- 報道を確認できない銘柄の媒体欄は「報道なし」とする。
- 「Mergermarketで出たらしい」と聞いていても記事の存在自体を確認できない場合は、Mergermarketの媒体フィルターへ入れない。「報道なし」に分類し、噂の説明欄で未確認と明記する。
- 会社が非公開化の検討に言及し、未決定と説明した例では、主タグは「検討に言及」、補足は「未決定」。主タグを一律「正式発表前」にしたいわけではない。

「報道なし」の読み方は、サイト全体の短い説明で「当サイトで報道を確認できていない銘柄を含む」と示す。報道が世の中に存在しないとの断定には使わない。毎行に長い注記を繰り返さない。

## 前仕様案から見直す点

1. 根拠を登録する仕組みと、公開画面の目立ち方を分ける。管理上は出典・確認方法を保持するが、一覧は媒体名と噂の概要を優先。個々の噂の意味を変える限定は短く添える。
2. 噂だけの銘柄に、確認済み報道の根拠URLを必須としない。噂の説明に書く範囲と、管理者専用の調査メモを分離する。非公開の個人情報を噂の根拠として公開させない。
3. 前案の「報道未確認」を一律の公開ラベルにする方針は、管理者指定の「報道なし」に変更する。内部の分類作業中とは引き続き区別する。
4. 主タグは「検討に言及」等の噂からの変化を含める。前案の主タグ9分類をそのまま確定仕様として実装しない。正式発表前／後／完了等は内部の段階分類とし、一覧の主タグとは別に持つ。
5. 一覧は「銘柄／媒体・噂の概要／今の状況／直近の変化」を軸に再検討する。フォント維持、複数媒体、株探リンク、検索改善の方向は継続。

## 公開表示の具体案（架空の例）

| A社 | 報道なし／非公開化をめぐる市場の噂。内容未確認 | 噂段階 | 追加情報は未確認 |

タグ語彙の全体案は、噂段階／提案受領／検討に言及／協議に言及／会社コメントあり／検討を否定／報道内容を否定／TOB等の実施発表／TOB開始／TOB成立／上場廃止／非公開化完了／検討終了／撤回／不成立など。全部を同じ階層の検索ボタンには並べない。「会社コメントあり」は内容を具体的に表せない場合の補助的な分類とする。

主タグの候補は記録した内容から提示し、根拠を示して管理者が選択する。新しい正式発表の後も過去の否定だけが主タグに残らないようにする。会社説明の主体・日付は直近の変化または補足に示す。噂の確度ランキングとしては扱わない。

「会社開示で確認」「有料原文未閲覧」などの詳しい根拠は、媒体を開くか詳細ページで読める構成にする。噂そのものが未確認であること、否定・未決定など読み取りを左右する注記は一覧から消さない。根拠は管理上保持するが、それがないことを理由に噂だけの登録を禁止しない。

## 管理画面の確認範囲

本番の管理者セッションで、会社・追跡銘柄・記事・プレビューの画面を操作。記事フォームに動作確認用の文を手入力し、未保存のプレビューと未保存時の公開承認ボタン無効を確認。確認用の入力は消去した。今回、本番にテスト銘柄・テスト記事を保存したり、公開処理を実行したりはしていない。

ローカルでは既存の `npm test` を実行し、114件成功。記事下書き保存・公開承認・公開版の分離・複数会社との関連・管理者権限・個人RLS・記事や報道のない公開銘柄の保持を含む。PGlite上の検証であり、本番への新規保存の確認ではない。最初の一部テスト直接実行は、入れ子のビルドに必要なnpm環境変数がなく1件停止し、正規のnpm testでは全件成功した。

直前の掲載作業では本番の会社・銘柄・記事の登録と公開まで実際に行っている。ただし、その実績だけで今回の入力導線の不具合がないとは扱わない。

## 現状の手順

- 新しい銘柄: 「追跡銘柄」→ 未登録なら「会社を登録」→ 会社保存 →「追跡銘柄」に戻る → 会社・タイトル・URL用slug等を入力 → 公開対象のチェックと保存 →「公開処理」で再ビルド。
- 新しい記事: 「記事・調査ノート」→「新規記事」→ 本文・出典・関連銘柄を入力 → 下書き保存 → 公開承認 →「公開処理」で再ビルド。
- 会社を登録するだけでは追跡対象の一覧・詳細は作成されない。記事に会社を関連付けただけでも、追跡案件は自動作成されない。

## 見つかった問題

### 1. 会社追加後、記事の関連銘柄一覧が更新されない（実画面で再現）

会社・追跡銘柄の選択肢にはイーソルがあるが、記事の関連銘柄にはなかった。記事タブの「一覧を再読込」を押すとイーソルが出た。

コードでも会社保存後は `loadCompanies` と会社・案件セレクトの再描画のみで、記事側の `reload` を呼ばない。記事タブへの移動でも再取得しないことを確認。

現在の回避方法は、会社を追加した後、記事を書き始める前に記事タブの「一覧を再読込」を押すこと。入力後に押すと未保存内容を破棄する確認が出るため、先に行う。改善時は入力を保持したまま会社候補だけを更新する。

### 2. 銘柄プレビューは入力中の内容を確認するものではない

コードでは保存済みの案件IDが必要で、画面上で編集している値ではなく、読み込んだ保存済みデータを表示する。新規入力は先に保存が必要。さらに本番にある追跡理由・確認状況などがプレビューに出ず、価格欄を生成する旧構成が残る。

実画面のイーソルのプレビューでは概要と出来事は表示されたが、入力フォームにある追跡理由・確認状況は表示されなかった。これでは本番に何が出るか十分に確認できない。入力中の値を用い、本番と同じ部品を使うプレビューにする必要がある。

### 3. 新規会社の保存後に、その会社のIDを編集フォームへ保持していない（コード確認）

新規会社保存はINSERT後に会社一覧を再取得するが、作成IDをフォームへ入れない。同じフォームで修正して再度保存すると、新規追加のまま扱われ、証券コードの一意制約で保存エラーになり得る。これは今回、本番で追加・再保存しての再現はしていない。

### 4. 銘柄登録は画面を往復し、slugも手入力する必要がある

「会社」と「追跡銘柄」が別操作であり、会社保存後に対象を自動選択して戻る案内はない。機能は存在するが、管理者が迷わず登録できる導線には改善余地がある。

## 改善候補

入口を「銘柄を追加」「記事を書く」の2つにする。

「銘柄を追加」はコード入力 → 既存会社の選択または新規会社入力 → 噂・媒体・状況 → プレビュー → 保存・公開、で完結。slugは重複確認付きで自動提案し、公開後の固定を維持する。記事は作成しない。

「記事を書く」は関連銘柄の選択 → 事実・本文・出典 → プレビュー → 下書き保存 → 公開承認。出典は記号区切りの手入力ではなく、名前・URL・日付の個別入力へ改善する案も含める。記事作成時に会社を追加した場合も、入力を失わず関連付けへ戻す。

これらは修正候補。今回の依頼では確認・すり合わせを行い、コード修正はしていない。
