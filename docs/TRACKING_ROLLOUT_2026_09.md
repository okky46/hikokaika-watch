# 媒体・噂・その後を中心にした改修

2026-09-29。`UX_ALIGNMENT_2026_09.md` の管理者回答を確定仕様として実装。実際の公開結果は `PROGRESS.md` の最新記録を参照する。

## 変更内容

- 一覧を「銘柄／媒体・噂の概要／今の状況／直近の変化」の4列へ整理。媒体の複数選択はOR、期間・会社説明などとはAND。全解除、条件のURL保持、戻る、詳細から一覧への条件復元に対応。
- 報道の存在が未確認なら「報道なし」。噂の文章中にMergermarket等があっても媒体フィルターには流用しない。記事・出典URL・出来事ゼロでも噂段階の銘柄を登録できる。
- 「提案受領」「検討に言及」「検討を否定」「TOB成立」「上場廃止」「非公開化完了」等を区別。未決定・説明主体・説明時点は補足に残す。予定日の到来だけでは更新しない。
- 媒体の確認方法、原文の閲覧範囲、出典URL、確認日、分類理由は詳細で展開。会社開示や二次報道による確認では原文未閲覧を維持する。
- 日時／日付／月／号数／不明を区別。登録日で公表日を補わない。直近12か月はJST当日を含む12か月区間。号数は希望時のみ参考年月で検索対象に含む。
- 銘柄にも下書き・承認済み公開版・版番号を追加。保存だけでは公開内容を変えず、承認時に関連項目をまとめて検証する。記事は従来どおり独立。
- 手動会社追加から銘柄・記事へ戻る際に入力を保持し、新しい会社を選択。再保存は同じ会社を更新。記事出典は区切り文字形式から個別欄へ変更し、特殊文字と改行を保持する。

## 管理画面での日常操作

1. 「銘柄を追加」→会社を選ぶ。未登録なら「会社を追加してここへ戻る」。登録内容は公開情報なので、非公開の個人情報や私的メモを入力しない。
2. 噂の概要、確認日、今の状況を入力。報道未確認なら「報道なし」と確認範囲を選ぶ。URLとタイトルは自動提案後に編集可能。初回公開後のURLと会社所属は固定。
3. 根拠のある報道なら媒体・出典・確認方法を追加。検討や成立等へ状況を進める場合は、先に「出来事」に根拠を保存し、銘柄側で「出来事を更新」して選ぶ。
4. 「下書き保存」→プレビューと変更項目を確認→「公開承認」→確認欄で実行。「公開処理」で再ビルドし、反映確認ボタンでこの環境の公開版を照合する。
5. 記事は「記事を書く」から独立して追加し、関連銘柄を選ぶ。噂だけの銘柄を記事にする必要はない。

日時の入力例は `2026-09-29T15:00:00+09:00`、日付は `2026-09-29`、年月は `2026-09`。号数には表示ラベルを入れ、参考年月は不明なら空欄。公開用の日付精度を指定済みの出来事は「追跡銘柄」で日付を編集・再承認する。出来事側の通常日時欄では上書きしない。

公開根拠として参照中の出来事を非公開にするには、先に銘柄の根拠・会社説明・日付指定から外して承認するか、銘柄を非公開にする。直接DBを変更して参照不整合が生じた場合、ビルドは安全のため停止する。

個人メモ・お気に入りは従来のログイン後の機能を使う。個人条件とメモは検索共有URLに含めない。管理者用の独立した調査メモ欄は今回追加していない。

## DBと公開手順

新規SQLは0009（媒体辞書、銘柄版、検証・保存・承認RPC）と0010（既存11銘柄の分類）。既存0001〜0004・0007・0008は変更しない。PR #8はマージしない。

Cloudflareの既存 `npm run build:cloudflare` がコード検証→DB履歴照合→追加SQL→サイト生成を実行する。管理者によるSQL手貼り、新しい鍵、DNSやGoogle認証設定の変更は不要。Previewはサンプルで、本番DBの更新をしない。

0010は既存ID・slug・証券コード・公開出来事の件数・ID・見出し・概要・出典URLを照合してから分類する。想定と異なるデータや既存の新分類がある場合は全件取り消して停止する。新しい案件・記事・出来事は追加しない。公開全件の承認済み分類がそろわない場合も新サイトのビルドを停止する。

旧サイトへの切り戻しはCloudflareの既存デプロイへ戻す。追加DBを削除したり、DB全体を巻き戻したりしない。旧サイトは従来の互換statusを読めるが、旧管理画面からの銘柄編集を併用しない。切り戻し中は公開編集を停止し、修正済み新管理画面へ復帰して再開する。
