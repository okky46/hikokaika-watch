# トップページのUI改善（2026-09-29）

PR #19の詳細デザインを本番反映後、トップの参考画像を管理者と調整。「初報の日付は概要の方に載せよう。それで実装してください」の指示により実装を承認済み。本番反映は別途判断する。以下の初期案と矛盾する場合は、次の最終合意を優先する。

## 最終合意と実装

- 見出しを控えめにし、既存フォント・フォールバック・等幅指定を維持。検索の段階はラジオボタンによるタブ風表示、媒体は複数選択ボタン、並び替えは一覧直上。URL復元・お気に入り・関心度・行クリック・外部リンクを維持する。
- 一覧は銘柄／媒体・噂の概要／今の状況と、右側に狭い株価・PER・PBR・EV/EBITDAの4列。数値は取得元が未確定のため「—」とし、未取得であることを共通表示。旧保存株価・架空値を流用せず、新規API・定期取得を追加しない。
- **初報日は概要欄へ置く。** 根拠の報道日と、報道イベントの日付精度を使う。会社回答日・サイト登録日を初報に置換しない。日付不明の先行報道があり得る場合は「日付確認済みの最初の報道」と補足し、噂だけなら未確認にする。
- 上に小さな段階・色の凡例。噂は灰、報道は淡い橙、検討・入札は橙、正式発表は青、完了は緑。否定・終了等は別表示。単なる会社コメントは進展扱いにしない。
- 入札の一次・二次・最終は、管理者が確認済み媒体の根拠と結び付いた出来事を選択して設定する。報道の本数・本文中の単語から推測しない。「参加を検討」と「入札が進んだ」も区別する。既存の会社説明の主タグは保持する。
- 管理者回答で**180日を超えた場合だけ淡色**を採用。90日段階は設けない。最終の公表日が分かる出来事からの日数で計算し、確認日・編集日ではリセットしない。日付不明・月・号数のみの出来事があるときは判定を保留。登録日で補完しない。正式発表後、完了、否定、撤回、終了は対象外。
- 背景だけを淡くし、本文のコントラストを保つ。「続報未確認・N日」と理由を表示。段階は巻き戻さず、検討継続・成立確率を表すものとも扱わない。静的生成に加え、閲覧時と日付変更時にブラウザー内で再判定し、追加取得リクエストは発生しない。

## DB・手動作業

`0011_tracking_bidding.sql` は公開分類JSONに任意の `bidding: {stage, event_id}` を許可する検証関数の追加対応。既存JSONを更新せず、新しい項目がない銘柄もそのまま利用できる。保存・公開RPC、ID、個人メモRLS、Auth、ドメインは変更しない。Cloudflareの本番公開前に既存の自動移行で適用する。管理者のSQL手貼り・新しい秘密情報・環境設定は不要。

公開後の運用: 銘柄編集の「報道で確認した入札段階」で段階と出来事を選び、下書き保存→プレビュー→公開承認→既存の公開処理。指定した出来事は「確認済み媒体の根拠」にも必要。正式発表・否定・終了等へ変更するときは入札段階を「指定なし」へ戻す。既存銘柄の入札段階を自動で埋めてはいない。

取得元の許諾確認・株価等の日次取得は引き続き別作業。初報前からの騰落率の計算基準はMARKET_METRICS_2026_09.mdに保持し、今回の承認画像の一覧には追加しない。

ロールバック時は、新しい入札分類を公開した後に旧コードで再ビルドすると旧検証が未知項目を拒否するため注意する。旧デプロイへの切替と旧コードでの再ビルドは区別し、旧コードへ戻す必要がある場合は新コードで入札指定を解除・承認するか、互換パーサーを維持する。通常の公開・SQL適用の結果はPROGRESS.mdに記録する。

## 画面確認で分かったこと

検索、媒体、期間、個人用条件、解除、件数が大きな検索カードに集まっている。390px幅では最初の画面がほぼ説明と検索で埋まり、銘柄を見るまでスクロールが必要。媒体チェックボックス、通常の青いリンク、ステータス表示が混在している。3列一覧・行クリック・確認日1か所・現在のフォントは維持する。

## 優先して実装したい案

1. **段階をタブへ**。「すべて／正式発表前／正式発表後／完了・終了」を件数付きで表示し、現在の「段階」ドロップダウンを置き換える。噂段階と観測報道等の細かな区別は常時表示の「今の状況」で選ぶ。「お気に入り」は段階と併用できる独立した切替にする。分類確認中の案件がある場合は選択肢を維持する。
2. **検索をコンパクトに**。会社名・コードの検索欄と今の状況を常時表示。並び順は検索枠から一覧直上へ移動。期間・会社説明の詳細条件は既存の折りたたみを使い、適用中の条件は折りたたみ外にも表示する。条件解除は条件がある時だけ目立たせる。検索URL・戻る操作・個人条件の扱いは維持。
3. **媒体を選択ボタンへ**。Mergermarket、選択、Bloomberg等を件数付きの小さなボタン風チェックボックスにする。選択時は背景色とチェック印で区別し、複数選択・キーボード操作を維持。0件は淡色で区別し、選択済み条件を勝手に消さない。報道なしの排他ルールは維持。
4. **一覧直上を整理**。左に結果件数と最終確認日、右に並び順。確認日の意味と並び順の詳しい説明は説明ボタン等から読めるようにし、長い説明を常時何行も並べない。確認日自体は1か所に常時表示する。
5. **行の操作感を統一**。今の3列を維持し、社名・媒体・状況の視覚的な区別と余白を整える。ホバーとキーボードフォーカスを明確にし、株探は詳細ページと同系統の小さなボタンへ。否定・未確認等の重要な状況補足は省略しない。
6. **スマートフォンのカードを短く**。社名と状況タグを上段に配置し、その下に媒体・噂の概要と状況補足をまとめる。各カードで繰り返す大きな項目名を減らす。本文や重要な但し書きを隠さず、縦の余白と重複表示を減らす。

上部の紹介文も短くまとめ、銘柄一覧が早く見えることを優先する。フォントは変えず、詳細ページと同じネイビー・白・薄いグレーの配色、丸み、ボタンの形を使う。大きな装飾画像や新たな集計カードは今回の主目的に含めない。
