## 1. サイトの目的と確定方針

「前に非公開化の噂になっていた銘柄、今どうなっている？」を確認するための、銘柄・案件単位の時系列データベースにする。

### 掲載対象

- 非公開化・MBO・親子上場解消などの噂や市場観測が出た銘柄を主に追跡する。
- Mergermarketや『選択』などの報道、市場での思惑、株価・出来高の動きを調査のきっかけにする。
- 事前の噂なく正式発表された非公開化案件を、網羅的に集めることは主目的にしない。
- 噂段階の銘柄も、管理者が登録・公開すれば一覧と詳細ページを作れる。記事や報道イベントの存在を掲載の必須条件にしない。
- 噂段階の登録から記事を自動作成・自動公開しない。記事として出さない追跡対象を持てるようにする。
- 親子上場の見直し、資本関係の再検討、戦略的選択肢への言及など、公表資料等を基にした記事も扱う。
- 記事と銘柄は独立して管理し、関連付けて相互にたどれるようにする。一つの記事から複数の銘柄を関連付けられること。

### 今回の範囲外

- OpenAI APIによる調査・生成は導入しない。ChatGPT／Codexの契約内で調査・ドラフトを作り、管理者が確認して公開する。
- 「APIを使わない」はOpenAI APIの方針。既存のSupabase認証・保存API等を撤去する意味ではない。
- X投稿の表示・埋め込み・検索リンク・自動収集の新規実装は行わない。
- 公開画面の株価チャートは当面表示しない。出来事マーカー付きチャートも将来候補に留める。
- 公開サイト用の新しい有料データサービスを、この方針だけを根拠に契約しない。
- 確認されていない噂の自動記事化・自動公開は行わない。

## 3. 画面・登録フロー

### 銘柄一覧

会社名・コード、追跡のきっかけ、現在の状況、最新の出来事または最終確認日を中心にする。
報道がない案件に「第0報」を表示しない。報道回数の熱量ランキングを主役にしない。

検索・絞り込みと既存のお気に入り導線を維持しつつ、最初に読む情報を絞る。
株価チャートは一覧・詳細とも非表示。必要に応じて株価指標欄も整理し、株探への導線を優先する。

### 銘柄詳細

1. 会社名・証券コード・追跡状況
2. 追跡理由・追跡開始日・確認状況
3. 経過タイムライン
4. 関連記事（公開済みだけ）
5. 本人用メモ・お気に入りへの導線
6. 株探チャート・業績へのリンク（Yahoo!ファイナンス等は補助導線）

記事も報道イベントもない銘柄の詳細が成立すること。
登録日、初報日、出来事の日付、最終確認日、サイト更新日を混同しない。
古い日付が不明なら推測で埋めない。株価取得日時を出来事の更新日時に使わない。

### 記事

ナビゲーションに「記事・調査ノート」を設け、一覧と詳細を追加する（想定URL: `/articles/`、`/articles/[slug]/`）。

- 記事は銘柄登録と独立した下書き・公開操作を持つ。

- 公表資料に基づく内容と編集上の解釈を混同しない。
- 既存の公開記事を編集する場合、意図しない再ビルドで未承認の編集を公開しないよう、公開版と編集中内容の扱いを設計する。

### 管理画面

- 「銘柄を登録・公開」と「記事を作成・公開」を別の操作にする。
- 会社未登録の場合も、会社と追跡対象の登録を迷わず進められるようにする。
- 銘柄は記事なしで公開可能。記事公開は管理者の明示操作による。
- 「保存済み」「公開待ち」「公開反映済み」を区別する。保存成功だけで反映済みと表示しない。
- 静的配信のため、公開処理・再ビルドが完了して一覧と詳細に反映されることを説明する。

## 4. 掲載と調査の扱い

本節は編集方針であり、法的安全性を保証するものではない。

- 噂段階の銘柄は一覧・詳細に掲載できるが、確定情報の記事にはしない。
- 「管理者の追跡対象として登録」と「非公開化の裏付けがある」を混同させない。
- 未読の有料記事について、記事本文を推測したり、聞き伝えを特定媒体の報道として断定したりしない。ユーザーはMergermarketや『選択』を購読していない。
- 公開見出し、二次報道、会社コメント等で確認できた範囲と、確認できない内容を分ける。
- 「噂」「疑問形」「免責文」があれば適法になるとは扱わない。一覧・詳細も公開情報である。
- 株価上昇を非公開化やインサイダー取引の証拠と断定しない。
- 会社による否定、訂正、検討終了も追跡する。「決定なし」を「検討なし」と読み替えない。
- 出典、当時の公表日、調査日を残し、発表後の後知恵を発表前の噂として記録しない。
- 具体的な掲載例・選定基準の法的評価は専門家への確認対象として残す。

過去12か月は、作業時に基準日と対象期間を記録する。「その期間に噂や動きがあった案件」を候補とし、必要な古い経緯も収録する。
月・検索語・銘柄別に調査し、一度の検索結果を網羅的な一覧と見なさない。
調査ドラフトを管理画面へ取り込める形式に整え、重複を照合して管理者が公開する。
新規のOpenAI API呼び出しやX連携を、この作業の前提にしない。
