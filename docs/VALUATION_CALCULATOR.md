# 株価・倍率の双方向試算

2026-10-03の合意に基づく実装。取得元は無料で使えるものに限る。市場株価は取得せず、閲覧者が入力する。EDINET APIキーはローカルの環境変数 `EDINET_API_KEY` のみで使い、ブラウザーや公開成果物には渡さない。

## 公開画面

銘柄の経過ページと企業ページで、株価からPER・PBR・EV/EBITDAを計算できる。逆に、入力した倍率から1株当たりの価格を試算できる。同じ比較業種のTOB事例から倍率を選ぶこともできる。入力値は保存・送信しない。

計算に使う財務数値には対象期、実績・会社予想、連結・単体、出典名、URL、注記を付ける。必要な値が未登録なら計算しない。確認済みの0と未取得を区別する。EPS・BPS・EBITDAが0以下、株式数が0以下、EV計算の範囲や残高基準日が不一致の場合も計算しない。負のEVや株主価値になる条件では、正の倍率・試算株価を表示しない。

PERは株価÷EPS、PBRは株価÷BPS。EVは時価総額＋有利子負債−現金・現金同等物＋その他調整額。EV/EBITDAから価格へ戻す際は、負債とその他調整額を控除し、現金を加算して株式数で割る。株式数は自己株式控除後。EPSは期中平均株式数を使うため、時価総額と当期利益から計算したPERとは差が出る場合がある。

各項目につき採用する数値は1つ。実績と会社予想を同時に切り替える機能は今回含まない。EDINETの実績値から会社予想を推定しない。会社予想を使う場合は会社の公表資料を確認して登録する。EBITDAの定義、リース債務、非支配持分、優先株、株式分割などの調整は注記に残す。銀行・保険などEV/EBITDAが適さない業種では、その計算項目を登録しない。

`/tob-comparables/` に過去案件を掲載する。TOB価格から計算した倍率と、算定資料に記載された倍率を区別する。価格の段階、採用した決算期、公表日、算定主体・根拠、価格変更の経緯を記録する。案件公表後に判明した決算値を、当時の既知情報と混同しない。

入力式の画面であることだけを理由に「投資助言に該当しない」とは判断しない。画面は入力条件による計算結果として表示し、自動的な推奨価格や売買推奨は掲載しない。

## EDINETから取り込む

公式API v2の仕様は [EDINET API仕様書](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/download/ESE140206.pdf) を参照。取得は手動実行し、停止中のニュース収集Action・Discord通知には接続しない。Python標準ライブラリだけで実行できる。

```powershell
python scripts/edinet_financials.py list --date 2026-10-02 --output outputs/edinet/list.json
python scripts/edinet_financials.py fetch --listing outputs/edinet/list.json --doc-id S100Z5LW --output outputs/edinet/candidates.json
```

上の書類IDは取得試験に使った訂正有価証券報告書の例。対象銘柄の一覧結果から、取り込みたい書類IDを選ぶ。過去年度の訂正書類を最新決算と扱わない。書類の取下げ・不開示状態を確認し、原資料でコード、対象期、連結範囲、単位を確認する。候補JSONには要素IDとコンテキストを残す。ZIPは展開せず読み、容量を制限する。

採用する候補を、次の形式の対応表に記録する。`ids` はその候補ファイル内のID。下の1は書式例で、実データの採用指示ではない。

```json
{
  "industry": "機械",
  "notes": "採用した決算期と株式分割の確認内容",
  "fields": {
    "eps": {
      "ids": ["1"],
      "period": "2026年3月期",
      "scope": "consolidated",
      "confirmedUnit": "円／株",
      "note": "原資料で通期EPSと分割調整を確認"
    }
  }
}
```

`confirmedUnit` はCSVの単位欄が空の場合だけ使用する。表示単位が百万円などの値を、倍率を推測して円へ変換しない。候補の単位が対応しない場合は原資料で換算し、管理画面で根拠付きで登録する。有利子負債などを合計する場合は同じコンテキストの重複しない項目を指定する。発行済株式総数をそのまま自己株式控除後株式数として採用しない。半期EPSを通期EPSの代わりに採用・年率換算しない。

```powershell
python scripts/edinet_financials.py compose --candidates outputs/edinet/candidates.json --mapping outputs/edinet/mapping.json --output outputs/edinet/financials.json
```

管理画面の「財務・TOB比較」でJSONを取り込み、項目と出典を確認する。出典リンクは認証なしで閲覧できるEDINET入口とし、書類ID・提出日・要素IDを併記する。APIキー付きの取得URLを出典欄へ貼らない。

取得結果だけで自動公開しない。EBITDA・有利子負債・調整額は企業ごとの定義を確認する必要がある。未確認項目は空欄のまま保存できる。実在案件の財務値・比較倍率は、このコード変更では本番へ登録しない。

## 保存・公開

1. 新規作成、または保存済みデータを選んで編集する。
2. 下書きを保存する。財務データは銘柄コードごとに1件、TOB事例は複数登録できる。
3. 保存内容を確認して公開対象にする。編集中のまま公開操作はできない。
4. 既存の「公開処理」で再ビルドし、詳細ページ・事例一覧の数値と出典を確認する。

DBは `0013_valuation_editions.sql` で追加する。適用済みSQLは変更しない。[自動更新手順](AUTO_DEPLOY.md)に従い本番公開前に適用する。管理者だけが下書きを読み書きでき、ビルド用RPCは公開版だけを返す。公開後に下書きを編集しても公開版は変わらない。更新が競合したときは内容を控えて再読込する。公開対象から外した後も、公開サイトへ反映するには再ビルドが必要。

既存メモ・お気に入り・認証・RLS・フォントは維持する。無料で公開利用できることを確認できない取得元、課金API、OpenAI API、株価スクレイピングは追加しない。
